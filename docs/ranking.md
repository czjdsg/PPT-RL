# 对决、排序与奖励

每个语义组单独向评审提交A/B完整原图，仅询问整体美学观感。各组有几页不影响其票权；tie双方0票。整份PPT分数是本场赢得的组数，谁更多谁胜。

canonical A/B按候选ID固定，display A/B由预先保存的种子选择。结果同时保存`displayed_winner`、归一化`winner`与映射；reason里的A/B按实际显示侧原样保留。同一方案复遇交换显示侧，每场判断都重新请求。

当前8候选double-elimination DAG在`bracket.py`，共14场。总决赛单场，不进行bracket reset；因此胜者组冠军可以一败获亚军。名次是1、2、3、4、5–6、7–8，奖励示例1/.8/.6/.4/.2/0。只在14场真实完成后输出完整名次，保留失败/缺失与人工决胜。

若主轮平分，`random_group_swap`固定种子抽一组并换序加赛，最多三组；主比分与加赛分别记录。这个默认规则不是模型审美全序的证明。`reward_conflicts`记录真实赢过对手但最终奖励更低的情况，不删除这些案例。

| 协议 | 总PPT对决数 | 工作量 |
|---|---:|---:|
| 单败 | n-1 | O(n) |
| 单套双败、单场GF | 2n-2 | O(n) |
| r套双败 | r(2n-2) | O(rn) |
| 偶数n的n-1套首轮不重复方案 | 2(n-1)^2 | O(n²) |

单败的O(log n)是平衡签表轮数/充分并行的依赖深度，不是总模型调用量。每整稿对决平均有g组时，审美调用再乘g。代码排序引擎目前显式支持8候选；一般n的公式不能被当成实现已支持任意n。

七套初始覆盖只保证28种首轮对手各出现一次，不代表105种首轮配对和全部签表位置的穷举。汇总使用已完成n的奖励均值、总体标准差、范围、冠军次数与档位频数；tau-b按5–6和7–8并列处理。重新判断、执行批次和签位路径都可能带来变化，不能做纯抽签因果解释或人类质量金标。
